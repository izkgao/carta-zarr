# Zarr test fixtures

The fixtures under `images/zarr` are generated by a pinned zarr-python reference implementation and
are committed so that the test suite does not depend on a Python toolchain. The generator is
self-contained: [`uv`](https://docs.astral.sh/uv/) reads the Python version and pinned dependencies
declared in the script.

Regenerate them from this directory:

```sh
./generate_zarr_fixtures.py
```

`images/zarr/string` covers the `fixed_length_utf32` codec layouts that the custom string decoder
must handle: valid zstd/gzip/blosc/crc32c chains and big-endian `bytes`, plus deliberately corrupted
checksum, truncated-chunk, and invalid-Unicode variants, a missing chunk, and the `v2` and `.`
separator chunk key encodings.

`images/zarr/xradio/minimal` is the XRADIO v1.2 multi-image reference dataset used by the schema
probe and descriptor tests. It carries shared coordinate, Stokes, storage, beam, mask, and
consolidated-metadata examples. Its spectrum is intentionally nonuniform. `SKY` itself has no
chunk files because all of its values equal the fill value, so pixel-read tests will need a fixture
with non-fill data. `images/zarr/xradio/legacy` retains the pre-root-`type` structural shape for the
legacy detection fallback.

These fixtures were moved from `carta-backend` (`test/data/`) and must keep the same layouts so the
extracted library preserves the backend's compatibility baseline. zarr-python emits its expected
unstable-extension warning for fixed-length UTF-32 arrays.

## Conformance fixture

`images/zarr/xradio/conformance` is produced by `generate_conformance_fixtures.py`, which pins
XRADIO itself rather than zarr-python: it writes a FITS image with astropy and converts it with
`xradio.image.open_image()` / `write_image()`. It is the record of what XRADIO actually writes, and
`tests/conformance_test.cc` asserts this library's assumptions against it, so bumping the pinned
XRADIO version reports which assumption the new version broke.

```sh
./generate_conformance_fixtures.py
```

This generator is heavier than the other one. XRADIO's `open_image()` imports its casacore layer
even for FITS input, and XRADIO excludes python-casacore on macOS, so `casatools` is required on
every platform. Its FITS reader is also strict: every axis needs `CTYPE` and `CUNIT` (including the
unitless Stokes axis), and the header must carry `LONPOLE`, `LATPOLE`, the `PC` matrix, and
`DATE-OBS`. Both generators are deterministic, so regenerating produces no diff unless a pinned
dependency changed.

Cases XRADIO cannot or will not produce — malformed metadata, an ambiguous flag, sharded storage,
corrupted string chunks, a store predating the root `type` marker — stay in the synthetic fixtures.
